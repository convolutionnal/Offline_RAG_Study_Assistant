1. Project Overview
1.1  Vision
A fully offline, privacy-first tool that takes any academic PDF — OS notes, DBMS slides, networking docs — builds a robust RAG pipeline on top of it, and generates grounded Multiple Choice Questions using a locally-running LLM. Zero cloud dependency. Zero API costs.

1.2  Problem Statement
Students preparing for exams face a wall of long, dense PDFs. Manually creating quiz questions is slow and inconsistent. Existing AI quiz tools either require internet connectivity, charge per query, or hallucinate content not actually in the source document. The goal is to solve all three problems at once.

4. PDF Parsing Strategy — Research-Backed
★  This is the most critical stage of the pipeline. Poor parsing produces garbage chunks, and garbage chunks produce hallucinated or irrelevant questions regardless of how good the LLM is.

4.1  Why pymupdf4llm as Primary Parser
Academic PDFs (lecture notes, textbooks) contain structural information — section headings, subsections, bold terms, tables — that raw text extraction destroys. pymupdf4llm converts each PDF page into structured Markdown, preserving:
H1/H2/H3 headings from font size and weight analysis
Bold terms (key definitions, important concepts)
Tables rendered as Markdown tables (| col | col |)
Code blocks and monospace sections
Page numbers and metadata attached as structured fields

This Markdown output is then fed to MarkdownHeaderTextSplitter — which is the key insight. The headers tell the splitter exactly where topic boundaries are, producing chunks that are semantically complete sections rather than arbitrary text windows.

4.2  Two-Pass Parsing Pipeline
Pass 1 — pymupdf4llm (Primary)
import pymupdf4llm

def parse_pdf_to_markdown(pdf_path: str) -> list[dict]:
    # Returns per-page markdown with metadata
    md_pages = pymupdf4llm.to_markdown(
        pdf_path,
        page_chunks=True,   # one dict per page
        show_progress=False,
    )
    return md_pages  # [{text: str, metadata: {page, source, ...}}]

Pass 2 — pdfplumber Fallback (for table-heavy pages)
import pdfplumber

def extract_tables_fallback(pdf_path: str, page_num: int) -> str:
    # Called when pymupdf4llm produces malformed table markdown
    with pdfplumber.open(pdf_path) as pdf:
        page = pdf.pages[page_num]
        tables = page.extract_tables()
        return format_tables_as_markdown(tables)

Quality Gate — Filter Useless Pages
MIN_TOKENS = 40   # pages with < 40 tokens are skipped (title pages, blank pages)
MIN_ALPHA_RATIO = 0.4  # at least 40% alphabetic chars (filters pure-number pages)

def is_useful_page(page_text: str) -> bool:
    tokens = len(page_text.split())
    alpha = sum(c.isalpha() for c in page_text)
    ratio = alpha / max(len(page_text), 1)
    return tokens >= MIN_TOKENS and ratio >= MIN_ALPHA_RATIO

5.2  Complete Chunking Implementation
Step 1 — Header Split
from langchain_text_splitters import MarkdownHeaderTextSplitter

HEADERS_TO_SPLIT_ON = [
    ("#",   "section"),
    ("##",  "subsection"),
    ("###", "subsubsection"),
]

def split_by_headers(markdown_text: str) -> list[dict]:
    splitter = MarkdownHeaderTextSplitter(
        headers_to_split_on=HEADERS_TO_SPLIT_ON,
        strip_headers=False,  # Keep headers in chunk text
    )
    docs = splitter.split_text(markdown_text)
    return docs  # Each doc has .page_content + .metadata with section names

Step 2 — Token-Bounded Recursive Split
from langchain_text_splitters import RecursiveCharacterTextSplitter
import tiktoken

ENCODING = tiktoken.get_encoding("cl100k_base")
MAX_TOKENS = 512
OVERLAP_TOKENS = 50

def count_tokens(text: str) -> int:
    return len(ENCODING.encode(text))

def split_to_token_limit(header_chunks: list) -> list[dict]:
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=MAX_TOKENS,
        chunk_overlap=OVERLAP_TOKENS,
        length_function=count_tokens,
        separators=["\n\n", "\n", ". ", " ", ""],
    )
    results = []
    for chunk in header_chunks:
        if count_tokens(chunk.page_content) <= MAX_TOKENS:
            results.append(chunk)
        else:
            sub = splitter.split_text(chunk.page_content)
            for s in sub:
                # Preserve parent metadata
                results.append({"text": s, "metadata": chunk.metadata})
    return results

Step 3 — Metadata Enrichment + Context Prepending
def build_final_chunks(token_chunks, source_file: str, page_num: int) -> list[dict]:
    final = []
    for i, chunk in enumerate(token_chunks):
        meta = chunk.get("metadata", {})

        # Build heading breadcrumb from metadata
        breadcrumb_parts = []
        for key in ["section", "subsection", "subsubsection"]:
            if key in meta and meta[key]:
                breadcrumb_parts.append(meta[key])
        breadcrumb = " > ".join(breadcrumb_parts)

        # Prepend breadcrumb to chunk text for embedding
        # This dramatically improves retrieval specificity
        text = chunk.get("text", chunk.get("page_content", ""))
        enriched_text = f"{breadcrumb}\n{text}" if breadcrumb else text

        token_count = count_tokens(enriched_text)
        if token_count < 30:   # Quality gate: skip noise fragments
            continue

        final.append({
            "chunk_id":    f"{source_file}:p{page_num}:c{i}",
            "text":         enriched_text,
            "raw_text":     text,          # original without breadcrumb
            "source":       source_file,
            "page_num":     page_num,
            "section":      meta.get("section", ""),
            "subsection":   meta.get("subsection", ""),
            "token_count":  token_count,
        })
    return final

7.4  MCQ JSON Schema (LLM Output Contract)
⚠  The LLM MUST return ONLY this JSON. No preamble, no explanation, no markdown fences. The validator will reject anything else and trigger a retry (max 3 attempts).

{
  "question":    "<non-empty string — the MCQ question>",
  "options": {
    "A": "<option text>",
    "B": "<option text>",
    "C": "<option text>",
    "D": "<option text>"
  },
  "correct":     "<exactly one of: A | B | C | D>",
  "explanation": "<non-empty string — why the answer is correct, citing the source>"
}


8. LLM Prompting Strategy
8.1  System Prompt
SYSTEM_PROMPT = """
You are an expert academic quiz generator. Your task is to generate
Multiple Choice Questions (MCQs) grounded ONLY in the provided context.

STRICT RULES:
1. Respond with ONLY a JSON object. No preamble, no explanation, no markdown.
2. Use EXACTLY this schema:
   {"question": str, "options": {"A":str,"B":str,"C":str,"D":str},
    "correct": "A"|"B"|"C"|"D", "explanation": str}
3. The correct answer MUST be explicitly supported by the context.
4. Distractors (wrong options) must be plausible but clearly wrong to someone
   who read the context.
5. Explanation must cite the specific concept from the context.
6. NEVER invent information not in the context.

DIFFICULTY GUIDELINES:
- easy:   Direct recall of a fact stated in the context
- medium: Requires understanding a concept or process
- hard:   Requires comparing, applying, or reasoning across concepts
"""

8.3  Retry Logic
MAX_RETRIES = 3

async def generate_with_retry(prompt, system_prompt, validator):
    for attempt in range(MAX_RETRIES):
        raw = await ollama_client.generate(prompt, system_prompt)
        try:
            parsed = output_parser.extract_json(raw)
            validated = validator.validate(parsed)
            return validated
        except (ParseError, ValidationError) as e:
            logger.warning(f"Attempt {attempt+1} failed: {e}")
            if attempt == MAX_RETRIES - 1:
                raise QuizGenerationError(f"Failed after {MAX_RETRIES} retries")
    return None
