=== TABLE 6 ===
Layer | Technology | Why This Specific Choice
PDF Parsing | pymupdf4llm | Converts PDF to Markdown preserving headings, tables, bold — essential for header-based chunking
Fallback Parser | pdfplumber | Handles PDFs with complex table layouts where pymupdf4llm loses structure
Chunking (primary) | MarkdownHeaderTextSplitter | Splits by H1/H2/H3 headers — creates semantically bounded chunks with section metadata
Chunking (secondary) | RecursiveCharacterTextSplitter | 512-token max with 10% overlap — applied after header split to keep chunks within embedding limit
Token Counting | tiktoken (cl100k_base) | Accurate token count to validate chunks fit embedding model context window
Embeddings | all-mpnet-base-v2 | Best general-purpose semantic model; 768-dim; GPU-accelerated via PyTorch; cached to E drive
Vector Store | ChromaDB | Local persistent vector DB; cosine similarity search; stores chunk text + rich metadata
LLM Runtime | Ollama + llama3.1:8b | Best balance of quality + speed for local structured JSON generation; mistral:7b as backup
Backend API | FastAPI + uvicorn | Async Python REST API; Pydantic validation; auto-generates OpenAPI docs at /docs
Frontend | React + Vite | Fast dev server; component-based UI for upload, controls, MCQ display

=== TABLE 7 ===
Noise Pattern | Cleaning Action
Hyphenated line breaks (pro-\ncess) | Rejoin: 'pro-\ncess' → 'process'  (regex: r'(\w+)-\n(\w+)')
Repeated page numbers (1, 2, 3) | Remove standalone numeric lines with regex r'^\s*\d+\s*$'
Header/footer boilerplate | Detect lines repeated across >3 pages and strip them
Unicode artifacts (●, ─, ▪) | Replace decorative unicode with standard ASCII equivalents
Multiple blank lines | Collapse 3+ consecutive newlines to double newline
Figure/table captions alone | Keep if followed by content; strip if isolated (e.g. 'Figure 2.1' alone on a line)
Reference/bibliography sections | Detect '[1] Author...' pattern and optionally skip entire section

=== TABLE 8 ===
Strategy | What It Does | Why It Matters Here
Header-aware split (primary) | Splits at H1/H2/H3 boundaries in Markdown output | Academic notes are organized by topic. Each section heading IS a semantic boundary. This is the single biggest quality improvement.
Recursive token split (secondary) | 512-token max, 50-token overlap, splits on \n\n → \n → . → space | Prevents header sections that are too long from breaking the embedding model context window
Token validation gate | Drop chunks < 30 tokens, cap at 512 tokens | Eliminates noise fragments and oversized chunks that dilute embeddings
Section metadata injection | Prepend heading path to each chunk text before embedding | 'Chapter 3 > Process Scheduling > FCFS Algorithm: ...' — makes embeddings dramatically more specific

=== TABLE 9 ===
Academic PDF Type | Expected Chunks | Strategy Result
Lecture notes (40-80 pages) | 150–400 chunks | Header-split gives one chunk per topic/subtopic — clean and precise
Textbook chapters (100+ pages) | 400–1000 chunks | Recursive split handles long prose sections; breadcrumb keeps context
Slide-exported PDFs | 100–250 chunks | Slide headers become section markers; short bullet content stays intact
Mixed (text + tables) | Varies | pdfplumber fallback preserves table rows; tables chunked as single units
