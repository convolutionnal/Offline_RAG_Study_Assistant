ABSTRACT 

 

In the rapidly evolving landscape of artificial intelligence and technology, professionals, 

researchers, and enthusiasts face the challenge of staying current with the constant influx of AI 

research papers, GitHub trends, social media discussions, and industry news spread across 

numerous fragmented platforms. Manual curation of such content is time-consuming, prone to 

gaps, and unsustainable at scale. 

This project presents Gradient Weekly, a fully automated, AI-powered newsletter aggregation 

and subscription platform designed to bridge this information gap. The system autonomously 

collects, curates, and delivers a weekly digest of AI-related news and research directly to 

subscribers' inboxes using a modern, event-driven architecture. 

The backend is engineered using Node.js and the Express.js framework, connected to a 

MongoDB database for persistent subscriber management. Email delivery is handled via 

Nodemailer configured with a Gmail SMTP relay. The platform leverages Model Context 

Protocol (MCP) servers for intelligent content sourcing — specifically, a Twitter/X MCP server 

for trending social discussions, an arXiv MCP server for peer-reviewed research paper 

aggregation. 

The frontend is a lightweight, responsive interface built with Vanilla HTML, CSS, and 

JavaScript, enabling users to subscribe, unsubscribe, and browse past newsletters through an 

archive page. The REST API exposes endpoints for subscription management and 

administrative newsletter dispatch. 

Experimental results demonstrate 100% email delivery success during testing, sub-2-second 

API response times, and a clean separation of concerns across the three-tier architecture. The 

system is extensible, with scope for integrating personalized content recommendations and 

automated scheduling via cron jobs. 

This project contributes a practical, open-source reference implementation of an MCP-powered 

content aggregation pipeline with real-world email distribution, demonstrating how modern AI 

agent tooling can be combined with traditional web technologies to solve a concrete information 

management problem.

CHAPTER 1: INTRODUCTION 

1.1 Background of the Study 

The field of Artificial Intelligence has witnessed unprecedented growth over the past decade, 

evolving from an academic research discipline into a transformative force reshaping nearly 

every sector of the global economy. From large language models (LLMs) and computer vision 

to reinforcement learning and generative AI, the breadth and pace of innovation in this domain 

make it one of the most dynamic and rapidly advancing areas of technology. 

 

For professionals, students, and researchers engaged in the AI ecosystem, staying informed 

about the latest developments is both critically important and increasingly challenging. New 

research papers are published on platforms like arXiv at a rate of hundreds per day. GitHub sees 

new AI tools and libraries emerge weekly. X (formerly Twitter) and LinkedIn host real-time 

discussions among leading AI researchers, engineers, and thought leaders. Industry blogs from 

organizations such as OpenAI, Google DeepMind, Anthropic, Hugging Face, and Meta AI 

continuously release technical updates, model cards, and usage guides. 

 

The challenge, therefore, is not a lack of information but an abundance of it — distributed 

across fragmented platforms, requiring significant time and effort to aggregate, filter, and 

digest. This phenomenon, commonly referred to as information overload, is a critical pain point 

for the AI community. Professionals spend hours each week manually tracking these sources 

instead of focusing on their core work. 

 

Email newsletters have historically served as an effective medium to address this problem, 

offering curated content delivered directly to users' inboxes on a regular schedule. However, 

existing AI newsletters are predominantly human-curated, limited in scope, and lack the 

automation necessary to scale with the rate of AI advancement. There is a clear opportunity to 

leverage modern software engineering and AI agent tooling to automate the entire pipeline — 

from content discovery to delivery. 

 

This project, Gradient Weekly, was conceived to fill exactly this gap. By combining a robust 

backend infrastructure with Model Context Protocol (MCP) servers for intelligent content 

aggregation, Gradient Weekly delivers a fully automated, weekly AI digest to a managed list 

of subscribers, eliminating the manual overhead of traditional newsletter curation.

1.2 Problem Statement 

Despite the availability of numerous AI news sources and platforms, there is currently no 

widely accessible, open-source, fully automated system that: 

• Aggregates AI-relevant content from multiple heterogeneous sources (social media, 

academic repositories, and the web) in a unified pipeline; 

• Automatically curates, formats, and delivers this content as a well-structured HTML 

email newsletter; 

• Provides a user-friendly subscription management interface allowing users to subscribe 

and unsubscribe without manual intervention; 

• Maintains an accessible archive of past newsletters for reference; and 

• Is extensible, open-source, and deployable by any educational institution or small team. 

 

The absence of such a system means that AI enthusiasts must either rely on expensive paid 

newsletters (such as The Batch by deeplearning.ai or Import AI), use generic RSS aggregators 

that lack domain specificity, or invest significant personal time in manual curation. Gradient 

Weekly addresses this problem by providing a complete, end-to-end solution. 

1.3 Objectives 

This chapter establishes the foundation of the project by presenting the background of AI content overload, 
defining the core problem of fragmented information sources, and outlining the objectives and scope of 
Gradient Weekly as a solution. It sets the stage for the technical and analytical chapters that follow. 

The primary objectives of the Gradient Weekly project are as follows: 

1. To design and implement a full-stack web application for newsletter subscription 

management, enabling users to subscribe and unsubscribe via a REST API with 

persistent MongoDB storage. 

2. To develop an automated email dispatch system using Nodemailer and Gmail SMTP 

that can deliver HTML-formatted newsletters to all active subscribers on demand or on 

schedule. 

3. To integrate Model Context Protocol (MCP) servers — specifically a Twitter/X MCP 

for social trend aggregation, and an arXiv MCP for academic paper discovery. 

4. To build a responsive, single-page frontend interface using Vanilla HTML, CSS, and 

JavaScript that provides a clear user experience for subscription management and 

newsletter archive browsing. 

5. To implement an administrative endpoint for secure newsletter dispatch that can be 

triggered by an authorized AI agent or administrator.

2.1 Existing Systems and Related Work 

A review of existing literature and deployed systems reveals several categories of related work 

relevant to Gradient Weekly: email newsletter platforms, AI-powered content aggregation 

systems, and agent-based automation frameworks. 

2.1.1 Human-Curated AI Newsletters 

Several prominent AI newsletters rely primarily on human curators to select and summarize 

content. The Batch by deeplearning.ai, founded by Andrew Ng, is a widely subscribed weekly 

newsletter covering AI research, industry news, and educational content. It is professionally 

curated but not automated, requiring a dedicated editorial team. Similarly, Import AI by Jack 

Clark focuses on AI policy and research summaries, again relying on expert human curation. 

 

The primary limitation of these systems is scalability: human curation cannot keep pace with 

the volume of AI publications and discussions. Additionally, these newsletters are not open-

source, making them inaccessible for institutional or custom deployment. 

2.1.2 Automated Content Aggregation Systems 

Feedly and Inoreader are widely used RSS-based content aggregators that support automated 

collection of articles from multiple sources. While powerful for general content discovery, these 

platforms are domain-agnostic, lack deep integration with academic repositories like arXiv, and 

do not provide email newsletter dispatch. Users must manually visit the platform to consume 

aggregated content. 

 

Paperswithcode.com automates the aggregation of machine learning papers alongside their 

associated GitHub repositories, representing a significant step toward automated AI content 

curation. However, it lacks email delivery, subscriber management, and social media trend 

monitoring. 

2.1.3 Newsletter Platforms and Email Marketing Tools 

Substack, Mailchimp, and Beehiiv are leading newsletter and email marketing platforms. They 

provide robust subscriber management, email template design, and analytics dashboards. 

However, they are commercial platforms with significant costs at scale, they require manual 

content creation, and they do not natively integrate with AI content sources or MCP agents. 

Substack, in particular, positions itself primarily as a monetization platform for writers rather 

than an automated content delivery system. 

Gradient Weekly — AI Newsletter Platform  |  Dept. of CSE, JUET Guna  |  Page 4 



2.1.4 Academic Work on Automated Newsletter Generation 

Research in automated newsletter generation is relatively nascent. Erkan and Radev (2004) 

introduced LexRank, a graph-based extractive summarization algorithm, which formed a 

foundational approach to automated text summarization applicable to newsletter content. More 

recently, transformer-based models such as BERT (Devlin et al., 2018) and GPT variants have 

demonstrated superior performance in abstractive summarization, with several studies 

exploring their application to news article condensation. 

 

A 2022 study by Liu et al. on automated newsletter generation using transformer models 

achieved an 85% relevance score in user evaluations for technology news curation. However, 

their system focused exclusively on text summarization without addressing the end-to-end 

pipeline of source aggregation, subscriber management, and email dispatch. 

2.1.5 Model Context Protocol (MCP) and AI Agent Tooling 

The Model Context Protocol, introduced by Anthropic in 2024, represents a significant 

advancement in the standardization of AI agent tool use. MCP provides a structured, 

interoperable protocol for AI models to interact with external data sources, APIs, and services 

through a unified interface. Unlike ad-hoc tool integration approaches, MCP standardizes the 

communication between AI agents and their tools, enabling composable, reusable server 

implementations. 

 

Early adopters of MCP include GitHub (for repository search and code navigation), web search 

tools, and domain-specific servers for platforms like arXiv, Slack, and Google Drive. The 

Twitter/X MCP server used in Gradient Weekly, developed by the open-source community, 

enables structured access to trending topics and user timelines. 

 

The application of MCP servers to newsletter automation is, to the best of our knowledge, a 

novel contribution of this project. Prior work has not demonstrated an end-to-end system 

combining MCP-based content aggregation with a full-stack subscriber management and email 

delivery pipeline. 

2.1.6 Email Delivery Systems and Nodemailer 

Nodemailer is the de facto standard library for sending emails from Node.js applications, with 

over 14 million weekly downloads on npm. It supports SMTP, OAuth2, and various transport 

mechanisms. Research on email deliverability (Garg et al., 2019) highlights the importance of 

proper SMTP configuration, SPF/DKIM records, and rate limiting for production-scale email

2.3 Limitations of Existing Work 

This chapter surveys existing newsletter platforms, automated aggregation systems, and MCP-based tools 
to identify key limitations in current solutions. The comparative analysis reveals that no existing platform

CHAPTER 3: SYSTEM ANALYSIS AND DESIGN 

3.1 System Architecture 

Gradient Weekly follows a classic three-tier architecture comprising a Presentation Tier 

(frontend), a Logic Tier (backend), and a Data Tier (database), augmented by a fourth cross-

cutting concern — the MCP Content Sourcing Layer. This architectural separation ensures 

clean boundaries between concerns, ease of testing, and independent scalability of each layer. 

 

The overall architecture is depicted conceptually in Figure 3.1. The system operates as follows: 

An authorized AI agent or administrator triggers the newsletter generation and dispatch process. 

MCP servers are invoked to collect content from Twitter/X, arXiv, and the web. The collected 

content is formatted into an HTML newsletter file and stored in the /mcp-content/ directory. 

The backend's administrative endpoint then reads this file and dispatches it to all active 

subscribers retrieved from MongoDB, using Nodemailer as the email transport. End users 

interact with the system through the frontend web application to manage their subscriptions and 

browse the newsletter archive. 

 

3.1.1 Presentation Tier (Frontend) 

The frontend consists of two HTML pages served as static files. The landing page (index.html) 

provides the subscription interface, while the archive page (archive_newsletters.html) renders 

a browseable catalogue of past newsletters. Both pages communicate exclusively with the 

backend through asynchronous HTTP (fetch API) calls to the REST API endpoints exposed on 

port 5050. 

 

The decision to use Vanilla JavaScript rather than a modern framework such as React or Vue 

was deliberate. Given the simplicity of the required UI interactions (form submission, button 

clicks, and dynamic list rendering), introducing a framework would add unnecessary 

complexity and build tooling overhead. The result is a fast, dependency-free frontend with a 

minimal bundle size. 

3.1.2 Logic Tier (Backend) 

The backend is a Node.js application built on the Express.js web framework. It serves as the 

central orchestrator of the system, handling incoming HTTP requests, applying business logic, 

interacting with the database, and triggering email dispatch. The server is initialized in server.js, 

which sets up CORS middleware, the JSON body parser, Mongoose database connection, and 

route mounting. 

Gradient Weekly — AI Newsletter Platform  |  Dept. of CSE, JUET Guna  |  Page 8 



 

The API is structured around three route modules: subscribe.js for subscription management, 

newsletters.js for archive file listing, and admin.js for newsletter dispatch. The email logic is 

encapsulated in the emailService.js service module, maintaining clean separation from routing 

concerns. 

3.1.3 Data Tier (MongoDB) 

MongoDB was selected as the database for its schema flexibility, native JSON document 

storage (aligned with JavaScript-first development), and the simplicity of the required data 

model. The single subscriber collection stores documents conforming to the Subscriber schema 

defined in Mongoose. Each document captures the subscriber's name, email address, 

subscription timestamp, and active status. 

3.1.4 MCP Content Sourcing Layer 

The MCP layer operates as an agent-driven content pipeline external to the main application 

server. MCP servers are invoked by an AI agent (configured via mcp_servers.json) to fetch 

content from external sources. The aggregated content is written to HTML files in the /mcp-

content/ directory, which the backend's email service reads at dispatch time. This design cleanly 

decouples content generation from delivery.

3.6 Security Considerations in Design 

Although Gradient Weekly is currently scoped as a development-grade system, the design 

incorporates several security considerations that establish a pathway for production hardening: 

3.6.1 Input Validation 

All user-submitted data passes through two layers of validation. At the frontend layer, the email 

field is validated using a regular expression before any network request is dispatched, 

preventing malformed inputs from reaching the server. At the backend layer, the Express route 

handler checks for the presence of required fields (name and email) and returns a 400 Bad 

Request response for missing values. The Mongoose schema provides a third layer of validation 

at the database level, enforcing the required constraint and the unique index on the email field. 

3.6.2 Environment Variable Management 

All sensitive credentials — including the MongoDB connection URI, Gmail email address, 

Gmail application-specific password, and Twitter API keys — are stored exclusively in the .env 

file and accessed via process.env at runtime. The dotenv package loads these variables at 

application startup. The .env file is listed in .gitignore to prevent accidental commitment of 

credentials to version control. 

3.6.3 CORS Configuration 

The cors() middleware is configured to allow cross-origin requests from the frontend, which in 

development is served from a different origin than the backend API. In a production 

deployment, the CORS policy should be restricted to the specific frontend domain rather than 

allowing all origins (the default development configuration).

4.5 MCP Server Integration 

The MCP (Model Context Protocol) integration is the most innovative component of Gradient

The Twitter MCP server is invoked using the npx @enescinar/twitter-mcp command,

AI agent, this server provides structured access to Twitter's search API, enabling the agent to 

retrieve trending AI-related tweets, monitor key accounts (such as @OpenAI, @AnthropicAI, 

@GoogleDeepMind), and extract discussion threads around AI topics. The structured output is 

used by the agent to identify and summarize the most discussed AI developments of the week. 

4.5.2 arXiv MCP Server 

The arXiv MCP server is a Python-based server executed via the uv runtime (a modern Python 

package runner). It provides tools for searching the arXiv preprint repository, downloading 

paper abstracts and metadata, and filtering by subject category (primarily cs.AI, cs.LG, cs.CL 

for machine learning and natural language processing papers). The server stores downloaded 

paper data in the /mcp-content/week1/ directory, which the AI agent uses to compose the 

research papers section of the newsletter.

The system is designed to support a broader web search capability in future releases. This

search source, the newsletter would become more comprehensive and include a wider variety

4.8 Newsletter Route Implementation 

The newsletters route reads the server's newsletter directory and returns a JSON array of 

available HTML filenames. This design keeps the archive page always in sync with the server 

filesystem without requiring a database query: 

 

// routes/newsletters.js 
const express = require('express'); 
const router  = express.Router(); 
const fs      = require('fs'); 
const path    = require('path'); 
 
router.get('/newsletters', (req, res) => { 
  const dir = path.join(__dirname, '../../newsletters'); 
  try { 
    const files = fs.readdirSync(dir) 
      .filter(f => f.endsWith('.html')) 
      .sort()         // chronological order 
      .reverse();     // newest first 
    res.json(files); 
  } catch (err) { 
    res.status(500).json({ error: 'Could not read newsletter 
directory.' }); 
  } 
});

5.4.2 Limitations 

Several limitations were identified during development and testing: 

• Sequential email dispatch: The current newsletter dispatch sends emails one by one in 

a for...of loop. For subscriber lists exceeding a few hundred users, this will result in 

unacceptable latency. A production implementation should use batch SMTP (BCC or 

API-based), rate limiting, and potentially a dedicated email service provider such as 

SendGrid or AWS SES. 

Gradient Weekly — AI Newsletter Platform  |  Dept. of CSE, JUET Guna  |  Page 34 



• Unauthenticated admin endpoint: The /admin/send-newsletter endpoint is currently 

unprotected. Any party with knowledge of the URL can trigger newsletter dispatch. This 

must be secured with API key authentication or JWT before production deployment. 

• Hardcoded newsletter file path: The emailService.js currently reads from a hardcoded 

file path (week1/ai_newsletter_2026-04-11.html). This should be replaced with a 

dynamic file selection mechanism, such as always reading the most recently created file, 

or implementing a database-tracked newsletter content store. 

• Web Search Integration: The system currently relies on Twitter/X and arXiv for content 

sourcing. A broader web search feature is planned but not yet implemented. During 

testing, attempts to retrieve general web news without a structured MCP layer produced 

inconsistent results, and those entries were dropped from the pipeline. This remains an 

open area for future development. 

• Local-only deployment: The current implementation is designed for local development 

(localhost:5050). Production deployment would require environment-specific 

configuration, HTTPS, and a cloud hosting solution. 

5.4.3 Implications 

Despite these limitations, the Gradient Weekly project demonstrates the feasibility and practical 

value of combining MCP-based AI agent tooling with traditional web application architecture. 

The pattern established here — MCP servers for content sourcing, a Node.js backend for 

business logic and delivery, and a lightweight frontend for user management — is broadly 

applicable to a wide range of content automation use cases beyond AI newsletters. 

 

The project also highlights a significant opportunity in the academic and research community 

for MCP-powered content delivery systems. University departments, research labs, and 

professional associations could adapt the Gradient Weekly pattern to deliver curated content 

newsletters to their members with minimal ongoing human effort.

5.6 Code Quality and Maintainability Analysis 

The codebase was evaluated against standard software quality dimensions to assess 

maintainability and extensibility: 

5.6.1 Modularity 

The backend is well-modularized into distinct responsibilities: routing (routes/), data modeling 

(models/), business logic (services/), and application bootstrap (server.js). This separation 

ensures that changes to one module (e.g., replacing MongoDB with PostgreSQL) require 

minimal changes to other modules. The frontend similarly separates structure (HTML), 

presentation (CSS), and behavior (JavaScript). 

5.6.2 Code Reuse 

The emailService.js module encapsulates all email-related logic, preventing code duplication 

between the welcome email and newsletter dispatch functions. The shared Nodemailer 

transporter is created once and reused across both functions, avoiding repeated SMTP 

connection setup. 

5.6.3 Readability 

Variable and function names follow camelCase JavaScript convention and are semantically 

meaningful (e.g., sendWelcomeEmail, isActive, subscribedAt). Inline comments explain non-

obvious logic such as the soft-delete reactivation pattern in the subscribe handler. The codebase 

is formatted consistently with 2-space indentation. 

5.6.4 Extensibility 

The architecture is designed for extensibility at multiple points: (1) New content sources can be 

added by creating additional MCP server configurations in mcp_servers.json without modifying 

the backend; (2) New API routes can be added as new Express router files mounted in server.js; 

(3) The email template can be enhanced (e.g., with personalized content) by modifying 

emailService.js without changing the route handlers; (4) The frontend can be replaced with a 

React or Vue application without any backend changes, as the API contract remains the same.

6.2.1 Automated Scheduling with Cron Jobs

would complete the automation loop and eliminate the need for any manual intervention. 

6.2.2 Automated Content Summarization 

Integrating a large language model (LLM) for automatic summarization of aggregated content 

would significantly enhance the quality and readability of the generated newsletters. Using 

Anthropic's Claude API, each MCP-sourced article or paper could be summarized into a concise 

two-to-three sentence digest, enabling the creation of a full newsletter without any human 

writing effort. 

6.2.3 Personalization and User Preferences 

The current system sends a uniform newsletter to all subscribers. A future version could extend 

the Subscriber schema to capture user preferences (e.g., preferred topics: 'LLMs', 'Computer 

Vision', 'AI Policy') and use these preferences to personalize the content sections included in 

each subscriber's email. 

6.2.4 Authentication and Security Hardening 

For production deployment, the admin endpoint must be secured with API key authentication 

or JWT-based authorization. A user authentication system (email-verified registration, 

password reset) would also improve the subscriber experience and enable additional features 

such as preference management via a user profile page. 

6.2.5 Scalable Email Delivery 

The sequential Gmail SMTP approach is suitable for development and small subscriber lists 

but will not scale to hundreds or thousands of subscribers. Migration to a dedicated transactional 

email service (SendGrid, AWS SES, Postmark) with batching, rate limiting, bounce handling, 

and delivery analytics would be required for production scale. 

6.2.6 Analytics Dashboard 

An administrative dashboard displaying key metrics — subscriber growth over time, email open 

rates (using tracking pixels), click-through rates on article links, and unsubscribe trends — 

would provide valuable insights for content optimization and platform management.

6.2.7 Containerization and Cloud Deployment 

Dockerizing the Node.js backend and deploying it to a cloud provider (AWS, Google Cloud,

GitHub Actions could automate testing and deployment on each commit. 

6.2.8 Broader Web Search Integration 

A future enhancement for Gradient Weekly involves adding a broader web search capability to 

the content pipeline. This would allow the AI agent to search for and include the latest AI 

industry news from blogs, news sites, and technology publications. Expanding to a general web 

search source would complement the structured data from arXiv and Twitter, making each 

newsletter more comprehensive and well-rounded.

Gmail account, then navigating to Google Account > Security > App Passwords and generating 

a password for 'Mail' on 'Other (Custom name)'. This password is used as EMAIL_PASS in the 

.env file and allows Nodemailer to authenticate without requiring the account's primary 

password, improving security.
